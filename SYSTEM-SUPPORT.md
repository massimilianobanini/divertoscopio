Le percentuali non devono essere duplicate o mantenute manualmente in altri file del repository: README, router, percorsi Player/Master e runtime devono leggere o rinviare a questa tabella.

## Regola runtime

Quando l'utente sceglie un sistema:

1. imposta `active_system`;
2. consulta questa tabella;
3. nel **primo messaggio successivo alla scelta del sistema**, mostra una sola volta un box breve di supporto;
4. poi continua normalmente con onboarding, preparazione o PLAY senza trasformare il box in un disclaimer lungo.

Formato canonico:

> **Supporto Divertoscopio — [SISTEMA]**  
> Confidence attuale: **[X%]**  
> *Stima interna basata su adapter, stress test e actual play. Non è una probabilità di divertimento né una garanzia che ogni ruling sia corretto.*

Se il sistema era già dichiarato nel primo messaggio dell'utente, mostra il box nella prima risposta utile.

Non ripetere il box a ogni turno. Mostralo di nuovo soltanto se:
- cambia `active_system`;
- l'utente chiede esplicitamente lo stato del supporto;
- una nuova sessione riparte con una scelta di sistema rilevante.

## Sistemi senza percentuale pubblica

Se l'utente sceglie un GDR che non compare nella tabella, **non inventare una percentuale**.

Usa:

> **Supporto Divertoscopio — [SISTEMA]**  
> Confidence attuale: **non valutata**  
> *Non esiste ancora una percentuale pubblica assegnata a questo sistema.*

Poi usa il percorso Unknown System Discovery quando necessario.

`COMPATIBILE` ≠ `TESTATO` ≠ `VALIDATO`.

## Aggiornamento della confidence

Una percentuale può cambiare solo quando cambia l'evidenza operativa del sistema, per esempio dopo:
- modifica o maturazione dell'adapter;
- nuovi stress test;
- nuovo actual play;
- regressioni o correzioni osservate.

Non aumentare o ridurre una percentuale soltanto perché il sistema è popolare, familiare al modello o apparentemente semplice.

Ogni modifica a questa tabella deve essere trattata come modifica esplicita dello stato pubblico di supporto del Divertoscopio.
